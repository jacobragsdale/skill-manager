skill-manager.json

A compatible source is a Git repository with a skill-manager.json file at its root. The manifest gives the source a stable name and maps repository files or directories to destinations on the user's computer.

Create a compatible repository

  1. Make the repository

    Put skill-manager.json at the top level of the repository's default branch. The repository must be reachable with an https:// or ssh:// Git URL. 

    example-source/
├── skill-manager.json
├── config/
│   └── settings.json
└── skills/
    └── review/
        └── SKILL.md

  2. Write the manifest

    Set version to 1. Give the source a stable id, then add one install entry for each file or directory.

    {
  "version": 1,
  "source": {
    "id": "example",
    "name": "Example source",
    "description": "Agent Skills and configuration files."
  },
  "installs": [
    {
      "id": "review",
      "source": "skills/review",
      "destination": "~/.agents/skills/example-review"
    },
    {
      "id": "settings",
      "source": "config/settings.json",
      "destination": "~/.config/example/settings.json"
    }
  ]
}
    Field Rule
    version Required integer. Must be 1.
    source.id 2–16 lowercase letters, digits, or single hyphens. Must begin with a letter.
    source.name Required display name, 1–120 characters.
    source.description Required description, 1–1,024 characters.
    installs[].id 1–64 lowercase letters, digits, or single hyphens.
    installs[].source Repository-relative regular file or directory.
    installs[].destination Absolute path or portable home-relative path beginning with ~/.

    Unknown fields are rejected. Install ids must be unique, and destinations in the same source cannot overlap.

  3. Check Agent Skill names

    A directory with SKILL.md at its root is treated as an Agent Skill. Its frontmatter name, install id, and source directory name must match.

    ---
name: review
description: Reviews a change before it is submitted.
disable-model-invocation: true
---

    Skill Manager prefixes the installed name with the source id. In the example above, review becomes example-review, so the destination directory must also end with example-review. The optional disable-model-invocation value must be a boolean.

  4. Check paths and limits

    • Directories are copied recursively. Executable permission bits are preserved where supported.
    • Symlinks, special files, globs, commands, hooks, and environment-variable expansion are not supported.
    • Use forward slashes in ~/ paths. Use a drive-qualified absolute path on Windows.
    • The manifest is limited to 1 MB. Selected content is limited to 2,000 files and 50 MB.

  5. Validate and publish

    Check the JSON before committing it:

    jq empty skill-manager.json

    For structural validation, save the v1 JSON Schema beside the manifest and run:

    npx ajv-cli validate --spec=draft2020 --strict=false \
  -s source-manifest.schema.json \
  -d skill-manager.json

    Commit and push the manifest with every referenced path. Add the repository URL in Skill Manager to check source files, Agent Skill names, destinations, symlinks, portability, and size limits.
